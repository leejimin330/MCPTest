## 1. 개요

포켓몬·디지몬 계열의 **캐릭터 육성 + 진화** 를 핵심으로 하는 2D 게임.
"돌보고 → 키우고 → 진화시키는" 루프에 집중한 다마고치 / 디지몬 월드 스타일이다.
탐험은 없고, 전투는 **조작 없는 자동전투**로 육성 결과를 시험하는 역할만 한다.

플레이어는 판타지 농장의 한 구역에서 케어(육성 대상 생물)를 돌본다. 먹이를 주고, 훈련시키고,
아이템을 장착시켜 스탯과 경험치를 쌓으면 조건에 따라 서로 다른 형태로 **분기 진화**한다.

키운 케어는 파티로 내보내 **자동전투**를 치르고, 그 보상으로 재화를 번다 (2026-08-13 추가).

### 한 줄 정의

> 농장에서 판타지 생물을 돌보며, 어떻게 키웠는지에 따라 다른 모습으로 진화시키는 2D 육성 게임.
> 키운 생물들은 파티로 내보내 자동전투를 치른다.

## 2. 목표와 비목표

### 2.1 이번 버전(MVP)의 목표

| # | 목표 | 성공 기준 |
|---|---|---|
| G1 | 육성 루프가 손에 잡힐 것 | 먹이주기 / 훈련하기 / 장착하기 3가지 액션이 각각 다른 상태값을 움직인다 |
| G2 | 진화가 "내가 키운 방식의 결과"로 느껴질 것 | 같은 기본형에서 **서로 다른 2가지** 진화형에 도달할 수 있다 |
| G3 | 데이터 확장이 쉬울 것 | 새 종·새 아이템·새 진화 조건을 **코드 수정 없이** ScriptableObject 에셋 추가만으로 넣을 수 있다 |
| G4 | 진행이 보존될 것 | 게임을 껐다 켜도 케어의 스탯/경험치/상태값/인벤토리가 유지된다 |
| G5 | 핵심 규칙이 검증될 것 | 진화 판정·육성 액션·세이브 로직이 자동 테스트로 커버된다 |

## 4. 핵심 게임 루프

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
  [케어 상태 확인]                                 │
   포만도 / 친밀도 / 스탯 / 경험치                  │
        │                                         │
        ▼                                         │
  [액션 선택]                                      │
   ├── 먹이주기   → 포만도↑ 친밀도↑ 경험치↑        │
   ├── 훈련하기   → 스탯↑ 경험치↑↑ 포만도↓ 친밀도↓ │
   └── 장착하기   → 스탯↑↑ 친밀도↑ (경험치 없음)   │
        │                                         │
        ▼                                         │
  [진화 조건 평가]  ← 액션 직후에만 판정            │
        │                                         │
        ├── 미충족 ─────────────────────────────────┘
        │
        └── 충족 → [진화 연출] → 새 형태로 계속 육성
```

**설계 의도:** 훈련은 강력하지만 포만도와 친밀도를 깎는다. 그래서 플레이어는
"훈련만 반복"할 수 없고 먹이주기와 번갈아 가며 자원을 관리하게 된다. 이 긴장이 육성의 재미다.

### 4.1 바깥 루프 (2026-08-13 추가, 2026-08-16 부화소로 순환 닫힘)

```
  [헛간에서 파티 편성]  ──▶  [전투터에서 상대 선택]  ──▶  [자동전투]
          ▲                                                   │
          │                                                   ▼
  [상점에서 장비·알 구매]  ◀────────────────────────  [재화 획득]
          │         │
          │         └──▶  [부화소에서 알을 깬다]  ──▶  [헛간에 새 케어]
          ▼
  [육성 루프로 되돌아가 더 키운다]
```

전투는 육성 루프의 **결과를 시험하는 곳**이지 별도의 축이 아니다.
지므로 잃는 것이 없어(부상·사망 없음) 실패의 대가는 시간뿐이고,
플레이어는 곧장 육성 루프로 돌아간다.

**순환이 닫혔다.** 번 재화로 상점에서 장비를 사 전투력을 올리거나, 알을 사서
**부화소에서 깨 새 케어를 얻는다**(2026-08-16). 알 → 새 케어까지 이어진다.

## 6. 기능 요구사항

### 6.1 케어 상태값

| 값 | 범위 | 초기값 | 설명 |
|---|---|---|---|
| 경험치 (Exp) | 0 이상, 상한 없음 | 0 | 누적만 되고 줄지 않음 |
| 공격 (Attack) | 1 이상 | 종별 기본치 | 전투형 스탯 |
| 방어 (Defense) | 1 이상 | 종별 기본치 | 전투형 스탯 |
| 체력 (Health) | 1 이상 | 종별 기본치 | 전투형 스탯 |
| **포만도 (Fullness)** | 0~100 | 60 | 높을수록 배부름. 훈련하면 소모 |
| **친밀도 (Bond)** | 0~100 | 30 | 먹이·아이템으로 오르고 훈련으로 조금 내려감 |

> **용어 정리:** 원 설계의 "배고픔"은 방향이 헷갈리므로 **포만도(Fullness, 높을수록 배부름)** 로
> 확정한다. UI에는 "포만도"로 표기한다.

### 6.2 육성 액션

| 액션 | 효과 | 실패 조건 |
|---|---|---|
| **먹이주기** | 포만도 +25 / 친밀도 +2 / 경험치 +5 | 포만도가 이미 100이면 거부 |
| **훈련하기** (스탯 선택) | 선택 스탯 +2 / 경험치 +15 / 포만도 −15 / 친밀도 −1 | 포만도 < 20 이면 거부 |
| **장착하기** (아이템 선택) | 장비 보너스 적용 / 친밀도 +3 / 경험치 없음 / 아이템은 **소모되지 않음** | 해당 아이템 보유 0개, 또는 이미 그것을 장착 중이면 거부 |
| **해제하기** | 보너스 제거 / 아이템은 인벤토리로 복귀 | 장착 중인 것이 없으면 거부 |

> **스탯은 두 층이다.** 훈련으로 오르는 **기본 스탯**은 영구적이고 세이브에 기록된다.
> **장비 보너스**는 장착 중에만 더해지고 빼면 사라진다. 진화 조건과 UI 는 둘을 합친 값을 본다.
> 슬롯은 **1칸**이라, 새로 장착하면 이전 장비는 인벤토리로 되돌아간다.

- 액션이 거부되면 상태값은 **전혀 변하지 않고** 사유 메시지가 표시된다
- 액션이 성공하면 **그 직후에만** 진화 조건을 평가한다 (매 프레임 판정 안 함)

### 6.3 장착 아이템 (MVP 구성)

아이템은 **전부 장착 아이템**이다. 소모품은 성격이 달라 나중에 별도로 다룬다.

| ID | 이름 | 장착 효과 | 초기 보유 |
|---|---|---|---|
| `hearty_feed` | 무쇠 발톱 | 공격 +3 | 3 |
| `iron_grain` | 돌 껍질 | 방어 +3 | 3 |
| `bloom_stone` | 블룸 스톤 | 체력 +5 | 1 |

### 6.4 진화 조건

조건은 여러 요구사항을 **AND** 로 묶는다. 지원하는 요구사항 3종:

- `ExpAtLeast(value)` — 누적 경험치가 기준치 이상
- `StatAtLeast(stat, value)` — 특정 스탯이 기준치 이상 (**장비 보너스 포함**)
- `RequiresEquipped(itemId)` — 특정 아이템을 **장착 중**일 것. 가지고만 있으면 안 된다

**MVP 진화 테이블**

| 결과 종 | 조건 | 우선순위 |
|---|---|---|
| 와일드비스트 | 경험치 ≥ 100 **AND** 공격 ≥ 15 | 1 (먼저 평가) |
| 블로섬 가디언 | 경험치 ≥ 100 **AND** `bloom_stone` **장착 중** | 2 |

> **알려진 밸런스 문제.** 공격 조건(15)은 경험치 조건(100)보다 먼저 충족되므로,
> 공격 장비를 껴도 진화 시점이 앞당겨지지 않는다 (둘 다 8행동). 장비가 진화 속도에
> 영향을 주게 하려면 두 임계치를 다시 잡아야 한다. 현재 상태는
> `WildbeastPath_IsGatedByExpNotAttack` 테스트가 고정해 두고 있다.

**향후 확장:** "장착 + 특정 상호작용"으로 진화하는 경로. 상호작용이 아직 정의되지 않아
요구사항 타입만 비워 둔 상태다.

- 두 조건이 동시에 충족되면 **목록 순서상 앞선 것**이 적용된다 (선택 UI는 이후 단계)
- 진화 시: 종 교체 → **스탯·경험치·포만도·친밀도 전부 유지** → 외형 갱신 → 로그 메시지 표시
- 진화형은 더 이상 진화 조건을 갖지 않는다 (MVP 기준 1단 진화)

### 6.5 화면 / 조작

**측면 뷰.** 화면 아래쪽에 땅 사각형이 깔리고, 캐릭터는 그 윗면(`y = −2.0`) 위에 서서
**좌우로만** 움직인다. 위아래 이동은 없다.

- 맵은 화면보다 넓다 (맵 반너비 **15**, 2026-08-15 에 13에서 늘림 vs 16:9 화면 반너비 약 **8.89**)
  → **드래그/터치 스와이프로 좌우 슬라이드**
- 슬라이드에는 관성 감속이 있고, 맵 밖은 보이지 않도록 카메라를 클램프한다
- 12px 이상 끌면 슬라이드로 간주해 건물 클릭이 발동하지 않는다
- 플레이어는 **A/D · ←/→** 로 좌우 이동, 맵 경계 밖으로 못 나감
- 파티원은 땅 위를 좌우로 **스스로 배회**한다 (목표 도착 시 잠깐 쉬고, 진행 방향으로 스프라이트 반전)
- **화면에는 상시 버튼이 없다.** 조작은 전부 건물/케어를 클릭해 여는 패널 안에 있다.
  상시로 보이는 것은 좌상단 상태 패널과 하단 로그 한 줄뿐이다

**패널 진입점**

| 패널 | 여는 방법 | 하는 일 |
|---|---|---|
| 육성 | **헛간 줄의 `[육성]` 버튼** | 먹이 · 훈련 3종 · 저장 |
| 창고 | 창고 건물 클릭 | 장착 / 해제 |
| 헛간 | 헛간 건물 클릭 | 파티 편성, 육성 대상 선택 |
| 상점 | 상점 건물 클릭 | 장비·알 구매 |
| 전투터 | **전투터 건물 클릭** | **맵 선택 → 스테이지 선택** 후 자동전투 (2026-08-16) |
| 부화소 | **부화소 건물 클릭** (2026-08-16) | 알 부화 |

필드의 케어를 클릭하면 **헛간으로 돌아간다** (육성 패널이 열리지 않는다).

### 6.7 세이브 / 로드

- 저장 위치: `Application.persistentDataPath/save.json`
- 포맷 **version 4** (v2 이하는 지원하지 않는다 — 만나면 새 게임으로 시작)
  - v2 → v3: 케어 **1마리 → 보유 배열 + 파티 인덱스 + 육성 대상 인덱스 + 재화**.

  - v3 → v4 (2026-08-16): **깬 스테이지 id 배열**이 늘었다. 필드가 느는 것뿐이라
    **버리지 않고 승격**한다 — 진행도만 빈 채로 시작하고 케어·재화는 그대로 산다
- 저장 내용: 케어별로 종 ID · **장착 아이템 ID** · 경험치 · **기본 스탯** 3종 · 포만도 · 친밀도,
  그리고 파티 인덱스, 육성 대상 인덱스, 재화, 인벤토리, **깬 스테이지 id**, 저장 시각
- **스테이지 진행도는 인덱스가 아니라 id 문자열이다.** 인덱스로 두면 스테이지를 중간에
  끼워 넣는 순간 진행도가 밀려 엉뚱한 스테이지가 깬 것이 된다. 대가로 **id 중복 금지**가
  불변조건이 됐다
- 스탯은 **장비 보너스를 뺀 기본값**만 저장한다. 보너스가 섞인 값을 저장하면 저장/로드를
  반복할 때마다 스탯이 불어난다 (`Capture_StoresBaseStatsNotBoostedOnes` 가 고정)
- 저장 시점: **UI의 저장 버튼**을 눌렀을 때 (자동 저장은 이후 단계)
- 로드 시점: 게임 시작 시 세이브 파일이 있으면 자동 로드, 없으면 새로 시작
- 종 ID로 실제 종 데이터를 되찾는 데는 `SpeciesDatabase` 를 쓴다. ID를 못 찾으면 로드를 실패
  처리하고 새 게임으로 시작한다 (깨진 세이브로 게임이 죽지 않게)

### 6.8 로스터 / 파티

```
보유(최대 8)  ⊇  파티(최대 4)  =  필드에 나와 있는 케어  =  전투 출전 멤버
```

파티를 편성·필드·전투로 나누지 않고 **하나의 개념**으로 둔다. "밖에 나와 있는 애들이
싸우러 간다" 는 규칙 하나로 설명되고 별도 편성 UI 가 필요 없다.

- **보유 목록의 순서는 절대 바뀌지 않는다.** 헛간 버튼이 이 인덱스를 persistent listener
  인자로 들고 있다. 파티 합류/복귀는 파티 목록만 바꾼다
- **육성 대상(`Target`)** 은 한 번에 한 마리. 헛간에서 고르고 창고·육성 패널이 함께 본다.
  대상이 사라지면 보유 목록 첫 번째로 되돌아간다
- 보유 8 / 파티 4 는 **씬 생성 시점에 고정**된다 (헛간 줄 수, 필드 슬롯 수).
  상한을 바꾸면 `BuildAll` 재실행이 필요하다

### 6.9 전투 (2026-08-16, 위치 기반으로 개편)

**자동전투.** 상대를 고르면 그때 파티가 그대로 출전하고 이후 조작은 없다.

**위치가 승패를 정한다.** 유닛은 전장에 흩어져 시작해 **가장 가까운 적**을 향해 걸어가고,
**사거리 안에 들면 멈춰 싸운다.** 같은 파티라도 어디에 떨어졌느냐에 따라 이기고 질 수 있다.

- **스폰은 난전이다.** 아군·적 구역을 나누지 않고 한 전장에 섞어 뿌린다
- **타겟은 가장 가까운 적이고 매 틱 다시 고른다.** 거리가 같으면 목록에서 앞선 쪽
- **이동 중에는 때리지 않는다.** 단 타이머는 계속 차서 붙는 순간 바로 나간다
- 사거리·이동속도는 **전 유닛 공통**이다(1.2 / 초당 2). 종별 차등은 아직 없다
- 겹치지 않도록 이동 중에는 서로 밀어낸다. **이 간격은 사거리보다 좁게 잘린다** —
  넓으면 유닛이 붙기 전에 밀려나 전투가 조용히 멎는다
- **시뮬레이터는 난수를 쓰지 않는다.** 스폰 좌표를 인자로 받을 뿐이다 —
  게임은 매번 다른 좌표를 넘겨 결과가 달라지고, 좌표를 고정하면 완전히 결정적이라
  EditMode 에서 시간을 흘려보내며 검증할 수 있다 (Q6)
- 피해 = **공격 − 방어/2** (최소 1). 방어를 절반만 반영해 방어 특화가 무적이 되지 않게 한다
- 각 유닛은 자기 **평타 간격**으로 때리고, 종 고유 **스킬**을 쿨다운마다 자동으로 쓴다
  - 스킬은 종당 하나이며 종 데이터에 직렬화된다. **진화하면 스킬도 바뀐다**
  - `Damage`(노리는 적에게 평타의 배수, **사거리를 지킨다**) /
    `Heal`(체력 비율이 가장 낮은 아군 회복, **사거리를 무시한다**) 2종. 적은 스킬이 없다
  - 회복만 거리를 무시하는 이유: 블로섬 가디언은 회복이 존재 이유인 진화 분기라,
    난전에서 거리 운에 값어치를 맡기면 분기 자체가 흐려진다
- 전투 스탯은 **장비 보너스를 포함**한다 — 장비를 끼면 전투가 실제로 세진다
- **전투는 케어에게 아무것도 남기지 않는다.** 깎인 체력은 전투 중에만 존재하고 부상·사망이 없다.
  패배의 대가는 시간뿐이라 몇 번이든 다시 도전할 수 있다
- 승리하면 쓰러뜨린 적들의 보상 합만큼 재화를 **한 번** 받는다

### 6.9.1 맵 / 스테이지 (2026-08-16)

전투터에 들어가면 **맵을 고르고, 그 맵의 스테이지를 고른다.** 스테이지는 **순서대로 해금**된다.

**계층 — 맵이 스테이지를 담는다**

```
StageMapDatabase
 └ StageMap  "들쥐 들판"   field = FieldMap(전장)
    ├ 들판 1  stageId "field_1"   들쥐 2       해금: (없음 — 항상 열림)
    ├ 들판 2  stageId "field_2"   들쥐 3       해금: 이전 스테이지 클리어
    ├ 들판 3  stageId "field_3"   멧돼지1+들쥐2  해금: 이전 스테이지 클리어
    └ 들판 4  stageId "field_4"   골렘 1       해금: 이전 스테이지 클리어
```

스테이지가 맵을 가리키지 않고 **맵이 스테이지를 담는다.** 전장을 한 번만 지정하면 되고,
화면 구조("맵 고르고 → 스테이지 고르고")와 데이터가 같은 모양이 된다.

**적 구성은 `entries` 리스트에서 인스펙터로 편집한다** — 종류와 마릿수를 줄 단위로 넣고 뺀다.
적 총원은 `BattleField.MaxEnemies`(8)를 넘을 수 없고, 넘으면 `BuildAll` 이 크게 실패시킨다.

**해금 조건 — 확장 가능한 목록**

전부 **AND**. 비어 있으면 항상 열린다.

| 종류 | 뜻 |
|---|---|
| `PreviousStageCleared` | 같은 맵의 바로 앞 스테이지를 깼는가. 첫 스테이지면 항상 만족 |
| `StageCleared` | 지정한 `stageId` 를 깼는가 (다른 맵도 가능) |
| `RequiresItem` | 아이템을 몇 개 이상 가졌는가 — **드랍 아이템(지도·열쇠)이 여기로 들어온다**(Q8) |

`if (이전을 깼는가)` 로 박지 않고 목록으로 둔 것은 **나중에 종류만 더하면 되게** 하기 위해서다.
진화 조건(6.4)이 이미 같은 모양이라 새로 배울 것이 없다.

**잠긴 스테이지는 회색 버튼으로만 두지 않는다.** 줄에 **왜 잠겼는지**를 적는다
("들판 1을(를) 깨야 한다." / "낡은 열쇠이(가) 필요하다."). 누를 수 없는 버튼은
무엇을 하면 열리는지 말해주지 않는다.

**화면 — 고정 6칸을 두 모드가 번갈아 쓴다**

맵 목록과 스테이지 목록이 **같은 6줄**을 나눠 쓰고, 6개를 넘으면 [이전]/[다음]으로 넘긴다.
행을 런타임에 만들지 않는 제약(6.12 함정) 때문인데, 덕분에 **스테이지를 늘려도
씬 재생성이 필요 없다** — 에셋만 고치면 된다.

**진행도**는 `stageId` 문자열로 세이브에 남는다(6.7). 기록되는 지점은 **승리 처리 한 곳뿐**이고,
연습 전투는 id 가 비어 있어 아무것도 남기지 않는다.

| 항목 | 종류 | 가격 |
|---|---|---|
| 무쇠 발톱 | 장비 | 30 |
| 돌 껍질 | 장비 | 30 |
| 블룸 스톤 | 장비 | 45 |
| 스프리글링 알 | 알 | 60 |

- 구매 규칙은 `ShopService.TryBuy` **한 곳**에 있다. **차감이 먼저**이고, 재화가 모자라면
  **아무것도 바뀌지 않는다** — 절반만 적용된 상태가 생기지 않는다. 가격이 0 이하인 항목은
  데이터 실수로 보고 거부한다
- 산 장비는 인벤토리를 거쳐 창고에 보유 수로 쌓인다 — 6.3 의 기존 장착 아이템과 같은 계통이다
- 산 알은 6.11 을 본다
- 판매 목록(`ShopStockDatabase`)이 상점 패널의 **행 개수를 그대로 정한다** — 항목을 늘리면
  씬 재생성이 필요하다 (`GameBootstrap.BuildAll`)

### 6.11 알 / 부화 (2026-08-16, 부화 구현)

- **알은 상점에서 산다.** `EggData`/`EggDatabase` 로 **`ItemData` 와 별개 계통**이다 —
  창고 행이 `ItemDatabase` 인덱스와 1:1 로 묶여 있어서, 아이템과 같은 계통에 두면 창고에
  알 행이 생겨버리기 때문이다
- 산 알은 인벤토리에 `egg_sprigling` 같은 키로 쌓이고 **창고에는 나타나지 않는다**
- 알은 **세이브 포맷을 안 바꿨다** — 인벤토리가 문자열 키 기반이라 그대로 실린다
  (포맷 자체는 2026-08-16 맵/스테이지 작업에서 v4 로 올랐다, 6.7)
**부화 규칙** (2026-08-16, `HatchService.TryHatch` 한 곳에 있다)

- **즉시 부화다.** 대기 시간이 없다 — 실시간 경과 시스템이 비목표(2.3)이므로 타이머를 두면
  게임을 꺼둔 동안 시간이 가야 하는지부터 정해야 한다. 그 결정을 부화에 끌고 들어오지 않았다
- **검사를 전부 끝낸 뒤에 알을 소모한다.** 부화는 인벤토리와 로스터 두 곳을 건드리므로,
  순서를 뒤집으면 "알은 사라졌는데 케어는 없다"가 실재한다. 상점은 "차감 먼저, 지급 나중"으로
  같은 보장을 얻었다 — 순서만 반대이고 보장은 같다
- **헛간이 가득 차면(8마리) 거부하고 알은 그대로 남는다.** 나온 케어는 `EggData.hatchesInto` 의
  종이고 기본 스탯·경험치 0 으로 시작한다
- **파티 합류는 부화가 하지 않는다** — 헛간에서 따로 넣는다. 보유와 파티는 별개 개념이다(6.9)
- 부화는 **세이브 포맷을 안 바꿨다** — 건드리는 인벤토리와 로스터를 이미 저장하고 있었다
- **한계:** 케어를 내보내는 기능이 없어 헛간이 차면 부화가 **영구히 막힌다** (9절 5번, Q7)

## 9. 이후 단계 (백로그)

의존 순서를 반영한 순서. 재화가 없으면 상점이 무의미하고, 몬스터가 한 마리면 헛간이 무의미하다.

```
✅ 전투 (재화 획득)  ──▶  ✅ 상점 (알·장비 구매)
   └ ✅ 위치 기반 교전     │
                             ├──▶  ✅ 부화소 (알 → 몬스터)
                             │              │
                             │              ▼
                             │         ✅ 헛간 (여러 마리 보관/교체) ──▶ ⬜ 케어 방출
                             │
                             └──▶  ✅ 창고 (장비 장착 UI)

        ⬜ 맵/스테이지 + 건물 씬 분리  ← 다음 순번 (전투터 씬 = 맵 선택 화면)
```

1. ~~**창고 UI**~~ — 완료 (2026-08-13)
2. ~~**전투**~~ — 완료 (2026-08-13). 자동전투 + 재화 보상
3. ~~**헛간**~~ — 완료 (2026-08-13). 세이브가 단일 → 배열(v3)로 바뀌었다
4. ~~**상점**~~ — 완료 (2026-08-15). 건물이 4동 → **5동**이 되어 전투 전용 건물(전투터)이
   따로 생겼고, 상점은 장비 3종 + 알을 판다 (6.10.1)
4-1. ~~**부화소**~~ — 완료 (2026-08-16). 알을 깨서 헛간에 새 케어를 넣는다 (6.11).
   **이것으로 MVP 순환이 닫혔다** — 전투 → 재화 → 알 → 케어 → 전투
4-2. ~~**위치 기반 전투**~~ — 완료 (2026-08-16). 유닛이 가장 가까운 적으로 걸어가
   사거리 안에서 싸운다. 배치가 승패를 정한다 (6.9). "좌표는 표시 전용"이 뒤집혔다
4-3. ~~**맵/스테이지**~~ — 완료 (2026-08-16). 전투터가 맵 → 스테이지 2단계가 되고
   **순서대로 해금**된다. 해금은 조건 목록이라 드랍 아이템이 나중에 그대로 물린다(Q8).
   세이브 v3 → **v4**. 화면이 고정 6칸 + 페이지라 **스테이지를 늘려도 BuildAll 이 필요 없다**
5. **건물별 개별 씬** ← **다음 순번** (2026-08-16 요청의 남은 절반).
   건물을 클릭하면 패널이 아니라 개별 씬으로 들어간다.
   **위험**: 씬 전환마다 저장 안 한 진행이 날아갈 자리가 생긴다 — 건물이 5개면 5곳이다.
   ~~옛 5번(맵/스테이지 + 건물 씬을 한 프로젝트로)~~ — 코드를 보니 겹치는 것은 전투터 화면
   하나뿐이라 갈랐다. 맵/스테이지를 먼저 끝냈다.
   전투터에서 맵을 고르고 맵마다 스테이지가 나뉘며, 건물은 패널이 아니라 개별 씬으로 들어간다.
   **전투터가 개별 씬이 되면 그 씬이 곧 맵 선택 화면**이라 따로 만들면 같은 화면을 두 번 만든다.
   `BattleEncounter` 계통 재구성 + 진행도 저장(세이브 변경 가능성)이 따라온다
6. **케어 방출** — 헛간 8마리가 차면 부화가 **영구히 막힌다** (Q7). 5번에 자리를 내주고 밀렸다
6. **상호작용 아이템 + 상호작용 진화** — "장착 후 특정 상호작용" 경로
7. **소모품** — 장착 아이템과 별개 계통으로 재도입
8. **다단 진화 / 종 추가**, **진화 선택 UI**, **실시간 경과**(부화 대기 시간 포함),
   **실제 아트**, **자동 저장**
9. **밸런스 재조정** — 6.4 의 "장비가 진화 속도에 영향을 못 준다" 문제. 전투가 생기면서
   장비는 **전투력**에 영향을 주게 됐지만 진화 시점은 여전히 경험치 병목이다
