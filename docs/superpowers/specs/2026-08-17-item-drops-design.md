# 몬스터 아이템 드랍 — 설계 (2026-08-17)

전투가 재화만이 아니라 물건도 준다.

---

## 1. 정한 것 셋

### 드랍은 **적**에게 붙는다

`EnemyData.drops` = `DropEntry`(itemId · chancePercent · count) 목록.
`goldReward` 와 같은 자리다 — "이 몬스터를 잡으면 이게 나온다" 가 데이터에서 바로 읽힌다.
스테이지에 붙이면 그 직관이 사라지고, 같은 적이 스테이지마다 다른 것을 떨구게 된다.

**id 는 `ItemData` 참조가 아니라 문자열이다.** 인벤토리가 문자열 키 하나로 아이템과 알을
함께 담기 때문이다(부화소 설계 4.3). id 로 두면 두 계통 어느 쪽이든 드랍할 수 있고,
**`StageUnlock.RequiresItem` 과 같은 키 공간**을 쓴다 — 드랍한 열쇠가 해금 조건에 그대로 물린다.

대가: 오타가 나도 컴파일이 안 막는다. 그래서 `GameDataIntegrationTests` 가
**실제 에셋으로** 모든 드랍 id 가 아이템이나 알에 실재하는지 대조한다.

### 확률은 쓴다. 단 **전투 밖에서** 굴린다

드랍이 확정이면 재화와 다를 것이 없다. 하지만 **`BattleSimulator` 는 난수를 부르지 않는다** —
그것이 이 프로젝트의 규율이고(위치 기반 전투 설계 2.5), 밸런스 하네스로 한 인카운터를
수천 번 돌릴 수 있는 이유다. 확률을 시뮬레이터 안에서 굴리면 그 성질이 깨진다.

→ **스폰 좌표와 같은 방식.** `DropResolver` 가 **seed 를 주입받아** 굴린다.
게임은 `BattleSceneRoot` 가 굴린 랜덤 seed 를, 테스트는 고정 seed 를 넘긴다.
**게임은 매번 다르고 테스트는 완전히 결정적이다.**

**`BattleSimulator` 는 한 줄도 안 고쳤다.**

### 결과는 로그에 적고, 인벤토리에는 한 곳에서만 넣는다

`BattleResult.Drops` 에 굴려진 결과를 실어 보내고, **`BattleReward.Apply` 한 곳**에서만
인벤토리에 넣는다 — 재화·진행도와 같은 자리다. 전투 씬은 결과만 나른다.

로그: `승리했다! 재화 16 획득. 블룸 스톤 x1, 스프리글링 알 x2 을(를) 얻었다.`

---

## 2. 승리할 때만 굴린다

재화와 같은 규칙이다. 그리고 **이기면 적이 전멸했으므로 인카운터의 적 전부가 대상**이다 —
그래서 시뮬레이터가 "누가 죽었는지" 를 따로 알려줄 필요가 없고,
`BattleEncounter.BuildEnemyList()`(한 마리씩 펼친 목록)를 그대로 넘기면 된다.

3마리면 세 번 굴린다. 같은 id 는 한 줄로 합쳐 돌려준다.

**쓸모없는 항목은 굴리지도 않는다** (빈 id · 0개 · 확률 0). 데이터 실수가 난수 순서를 바꾸면
같은 seed 로도 결과가 달라져 재현이 깨지기 때문이다.

---

## 3. 이름 찾기를 Core 로 올렸다

드랍 로그와 화면의 소지품이 **같은 규칙**으로 이름을 찾아야 한다.
`Core/ItemNames.Of(id, items, eggs)` 한 곳에 두고 `PanelLabels` 가 그것을 부른다.
못 찾으면 id 를 그대로 돌려준다 — 감추면 소지품이 조용히 사라진다.

> 이 규칙이 없어서 **좌상단 소지품이 `hearty_feed x3` 처럼 id 를 그대로 보여주고 있었다.**
> id 는 표시 이름과 어긋나 있다(`hearty_feed` = 무쇠 발톱). Play 로 보고서야 찾았다.

---

## 4. seed-only 데이터에 새 항목을 넣는 법

`EnemyData` 는 `LoadOrSeed` 라 **이미 있는 에셋은 손대지 않는다**(함정 3.11).
그런데 드랍은 기존 에셋에 없던 항목이라 그 규칙대로면 영영 안 들어간다.

에셋을 지우고 다시 깔면 되지만, **`BattleEncounter` 들이 이 적들을 참조하고 있어
지우면 스테이지의 적 참조가 전부 끊긴다.**

→ 지우지 않고 **"비어 있을 때만 채운다"** (`FillDropsIfEmpty`).
인스펙터에서 손댄 표는 절대 덮지 않고, 새로 생긴 항목만 흘려넣는다.
표를 비워두고 싶으면 항목 하나를 **확률 0** 으로 남겨두면 된다.

**일반화: seed-only 데이터에 필드를 추가할 때는 "없는 것만 채우는" 이주 단계가 필요하다.**
지우고 다시 까는 것은 그 에셋을 참조하는 것이 없을 때만 안전하다.

## 5. 씨앗과 의도

| 적 | 드랍 | 확률 |
|---|---|---|
| 들쥐 | 무쇠 발톱 | 15% |
| 가시멧돼지 | 돌 껍질 | 25% |
| 바위골렘 | 블룸 스톤 / 스프리글링 알 | 35% / 10% |

**블룸 스톤이 전투로도 나온다** — 진화 분기(블로섬 가디언)가 상점 구매 하나에만 매여 있지 않게 된다.

**아직 안 본 것**: 확률이 실제로 터지는 장면. 들쥐 15% 를 두 판 굴려 둘 다 꽝이었다.
**첫 스테이지 15% 가 너무 짠지는 밸런스 단계에서 볼 것** (한 판에 들쥐 2마리 → 약 28%).

## 6. 무엇이 이것을 지키는가

| 검사 | 잡는 것 |
|---|---|
| `DropResolverTests`(9) | 100%/0% / 마리마다 굴리는가 / 같은 seed = 같은 결과 / 다른 seed 는 갈리는가 / 합치기 / 잘못된 데이터 |
| `BattleRewardTests`(드랍 5) | 인벤토리에 들어가는가 / 이름으로 적는가 / **지면 안 주는가** / 잘못된 항목 무시 |
| `GameDataIntegrationTests` | **실제 에셋의 드랍 id 가 실재하는가** (오타 방지) |
| PlayMode `Victory_CarriesAResolvedDropList` | 전투 씬이 실제로 굴려서 실어 보내는가 |

**마지막 것이 중요하다** — 안 실으면 증상이 "드랍이 영원히 안 나온다" 뿐이라
확률 탓으로 오해하기 쉽다.
