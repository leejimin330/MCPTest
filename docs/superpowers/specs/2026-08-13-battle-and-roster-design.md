# 설계 — 전투 · 로스터 · 파티 (2026-08-13)

> **이 문서는 사후 기록이다.** 2026-08-13 밤 작업은 설계 문서 없이 진행됐다.
> 2026-08-14 에 코드·주석·테스트에서 결정과 근거를 복원해 옮겼다.
> 코드에 근거가 남아 있지 않아 **추정한 부분은 "(추정)" 으로 표시**했다.

**전제:** 같은 날 오후의 `2026-08-13-building-panels-design.md` 에서 이어진다.
그 문서는 "전투는 명세가 올 때까지 착수하지 않는다" 로 끝나지만, 같은 날 명세가 도착해
전투까지 진행됐다. 이 문서가 그 이후의 상태를 기술한다.

| 계층 | 추가 |

## 2. 전투

### 2.1 자동전투 — 조작이 없다

상대를 고르면 그때 밖에 나와 있는 파티가 그대로 출전하고, 이후 플레이어 입력은 없다.
각 유닛이 자기 타이머로 평타와 고유 스킬을 쓴다.

### 2.2 난수를 쓰지 않는다 ★설계의 중심

`BattleSimulator` 는 `Random` 도 `UnityEngine` API 도 부르지 않는다. 같은 입력이면 같은 결과다.

- EditMode 에서 원하는 만큼 시간을 흘려보내며 결과를 단언할 수 있다 (`BattleSimulatorTests` 13개).
- 밸런스를 만질 때 "운이 나빴나" 를 배제할 수 있다.

대가로 매번 같은 상대에게 같은 결과가 나온다. 회차마다 결과가 흔들리길 원한다면
난수를 넣는 것이 아니라 **시드를 외부에서 주입**하는 편이 이 구조를 지킨다. (추정)

### 2.3 시간은 `Tick(deltaTime)` 으로만 들어온다

시뮬레이터가 프레임을 모른다. `BattlePanel.Update` 가 `Time.deltaTime` 을 넘길 뿐이다.
배속·일시정지·즉시 결과 계산이 전부 호출 쪽 문제가 된다.

긴 `dt` 방어로 **한 틱에 유닛당 행동 8회** 상한을 둔다(`MaxActionsPerTickPerUnit`).
없으면 알트탭 후 복귀 같은 큰 `dt` 하나에 전투가 통째로 끝난다.

### 2.4 피해 공식 (초안)

```
피해 = 공격 − 방어/2      (최소 1)
```

방어를 절반만 반영한다. 전부 반영하면 방어 특화가 완전 무적이 되고, 최소 1 이 없으면
고방어 상대에게 전투가 끝나지 않는다.

**"초안" 인 이유:** 적 3종에 맞춘 값일 뿐 검증된 곡선이 아니다. 상대가 늘면 다시 볼 것.

### 2.5 스킬

종마다 **하나**. 별도 ScriptableObject 계통을 만들지 않고 `CreatureSpeciesData` 안에
`SkillDefinition` 으로 직렬화한다 — 스킬 교체·습득이 없어 종 데이터와 수명이 완전히 같다.
**진화하면 종이 바뀌므로 스킬도 함께 바뀐다.**

| 효과 | 대상 | 계산 |
|---|---|---|
| `Damage` | 살아 있는 첫 적 | 평타 피해 × 배수 |
| `Heal` | **체력 비율이 가장 낮은** 아군 | 시전자 공격력 × 배수 |

적은 스킬이 없다 — 평타만 친다.

### 2.6 전투는 케어에게 아무것도 남기지 않는다 ★

`BattleUnit` 은 전투 중에만 존재하는 별개 객체다. 여기서 깎인 체력은 `CreatureInstance` 에
반영되지 않는다. **부상도 사망도 없다.**

패배의 대가는 시간뿐이고 몇 번이든 다시 도전할 수 있다. 육성 게임의 축이 전투가 아니라
육성이므로, 전투 실패가 육성 자산을 파괴하지 않게 했다. (추정)

`BattleUnit.FromCreature` 는 **장비 보너스를 포함한** 스탯을 쓴다 — 장비를 끼면 전투가 실제로 세진다.
체력 스탯이 그대로 최대 체력이 된다.

### 2.7 로그와 보상

로그는 40줄 상한(`MaxLogLines`)으로 오래된 줄부터 버린다. 화면에는 마지막 8줄만 보인다.
보상은 쓰러뜨린 적들의 `goldReward` 합이고, `BattlePanel` 이 `rewardGranted` 로 **한 번만** 지급한다.

## 3. 로스터 · 파티

```
보유(Members, 최대 8)  ⊇  파티(Party, 최대 4)  =  필드에 나와 있는 케어  =  전투 출전 멤버
```

파티를 세 가지(필드·전투·편성)로 나누지 않고 **하나의 개념**으로 뒀다.
"밖에 나와 있는 애들이 싸우러 간다" 는 규칙 하나로 설명되고, 별도 편성 UI 가 필요 없다.

### 3.1 보유 목록의 순서는 바뀌지 않는다 ★

헛간 패널의 버튼이 이 인덱스를 **persistent listener 의 int 인자**로 들고 있기 때문이다
(HANDOFF 함정 3.6: Object 인자는 직렬화되지 않아 int 인덱스만 쓸 수 있다).
파티 합류/복귀는 보유 목록을 건드리지 않고 파티 목록만 바꾼다.

같은 이유로 헛간 줄 수는 `Roster.MaxMembers`(8) 로, 필드 슬롯은 `Roster.MaxParty`(4) 로
**씬 생성 시점에 고정**된다. 상한을 바꾸면 `BuildAll` 재실행이 필요하다.

### 3.2 `GameState` — 넘겨야 할 것을 하나로 묶는다

케어 1마리 시절에는 `CreatureInstance` 와 `Inventory` 를 따로 들고 다녔다. 파티와 재화가
생기며 인자가 늘어 한 덩어리로 모았다: `Roster` · `Inventory` · `Gold` · `Target`.

- **`Target`** — 먹이·훈련·장착이 적용될 케어. 헛간에서 고르고, 창고·육성 패널이 함께 본다.
  육성 액션은 전부 "누구에게" 가 필요한데 그 답이 한 군데 있어야 패널끼리 어긋나지 않는다.
  `EnsureTarget()` 이 대상이 사라졌을 때 보유 목록 첫 번째로 되돌린다.
- **`Gold`** — `AddGold` 로만 늘고 `TrySpendGold` 로만 준다. 부족하면 아무것도 바꾸지 않는다.
  **현재 소비처가 없다** (상점 미구현).

## 4. 화면 배선

- **`PartyField`** — 슬롯 4개가 씬에 미리 만들어져 있고 인원수에 맞춰 켜고 끈다.
  런타임 생성을 쓰지 않는 이유는 패널 행과 같다: 생성된 오브젝트의 스프라이트 참조가
  씬에 남지 않고, `SceneIntegrityCheck` 도 볼 수 없다.
  겹쳐 서지 않도록 필드 폭을 인원수로 나눠 배치한다.
- **필드의 케어를 클릭하면 헛간으로 돌아간다** (`CareManager.ReturnToBarn`).
  육성 패널 열기와 다른 동작이므로 주의 — 육성은 헛간 줄의 `[육성]` 버튼이 진입점이다.
- **진화 시 겉모습 갱신** — `Apply()` 가 진화를 감지하면 `PartyField.RefreshVisuals()` 로
  색·크기를 즉시 바꾼다. 슬롯 배정은 건드리지 않는다.
- **`RefreshAll()`** — HUD 와 **열려 있는 패널만** 다시 그린다. 실패한 액션 뒤에도 부른다.
  거부 사유를 패널이 안내하고 있어서, 갱신하지 않으면 로그와 패널이 서로 다른 말을 한다.

## 5. 세이브 v3

v2 → v3 에서 케어 1마리 구조가 **로스터 + 파티 + 재화**로 바뀌었다.
**v2 이하는 지원하지 않고 새 게임으로 폴백**한다 (v1 때와 같은 정책).

```
creatures[]      보유한 케어 전부. 이 순서가 헛간 목록 순서다
partyIndices[]   creatures 인덱스. 저장된 순서가 곧 파티 순서
targetIndex      육성 대상. 범위를 벗어나면 0 으로 되돌린다
gold
itemIds[] / itemCounts[]   JsonUtility 가 Dictionary 를 못 다뤄 병렬 배열로 평탄화
```

**스탯은 기본 스탯만 저장한다** (v2 와 동일). 장비 보너스를 저장하면 불러올 때마다
효과가 중복으로 얹혀 스탯이 불어난다. 복원 시 장착 아이템을 다시 끼워 보너스가 자동으로 붙는다.

`SaveSerializer` 는 **파일 IO 를 하지 않는다** — 파일 시스템 없이 라운드트립을 테스트하기 위함이다.
IO 는 `SaveSystem` 이 맡는다.

## 8. 임시 상태 · 미해결

### 8.1 상점 건물이 전투터를 연다 ★다음 작업의 걸림돌

전투에 전용 건물이 없어 `GameBootstrap` 이 `BuildingKind.Shop` → `BattlePanel` 로 배선했다
(`GameBootstrap.cs:497`). **상점을 만들려면 전투 진입점을 먼저 옮겨야 한다.**
선택지는 건물 5동으로 늘리기 / 필드 바깥 별도 진입점 / 상점 안에 전투 탭 — **미결.**

### 8.2 부화소

패널이 없다. 클릭하면 "알 시스템 준비 중" 로그만 뜬다.
알을 얻는 경로(상점 구매/전투 드랍)가 정해지지 않아 착수하지 않았다.

### 8.3 재화에 쓸 곳이 없다

`Gold` 는 전투로 쌓이기만 하고 `TrySpendGold` 를 부르는 곳이 없다. 상점이 생겨야 순환한다.

### 8.4 남아 있는 것

- **밸런스** — 8/6 부터의 "장비가 진화 속도에 영향을 못 준다" 문제는 그대로다.
  전투가 생기면서 장비가 **전투력**에는 영향을 주게 됐지만 진화 시점은 여전히 경험치 병목이다.
- **git 저장소 없음** — 되돌릴 지점이 없다. 이 문서도 커밋되지 않는다.
